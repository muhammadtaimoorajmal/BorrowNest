## 1. Scope & Methodology

This acceptance matrix evaluates BorrowNest's end-to-end functionality, local-first boundary enforcement, data integrity, and physical loan lifecycle correctness.

### Distinction Between Automated and Manual Checks
- **Automated Verification [AUT]**: High-fidelity transactional state machine and headless DOM tests executed under Vitest 5 with simulated storage (`fake-indexeddb`).
- **Manual / Visual Browser Verification [MAN]**: Human-inspected workflows conducted on a local Vite preview server instance (`http://localhost:4173/`) and the live GitHub Pages site across desktop and mobile viewports.

> [!NOTE]
> Usability findings reported herein reflect heuristic evaluations against Nielsen-Molich principles and WCAG 2.2 Level AA accessibility criteria. No informal or formal multi-participant lab studies are claimed.

## 3. Verified System Limitations

The following limitations are inherent to the current client-side prototype architecture and are documented transparently:

1. **No Inter-Browser Synchronization**: Listings, borrow requests, and condition records created in one browser are stored strictly in that browser's IndexedDB and are not broadcast to other users' devices.
2. **Local Dual Perspectives**: "Borrower View" and "Owner View" represent task workflows for evaluating lending interactions on a single machine. No remote user accounts, authentication tokens, or network sockets exist.
3. **Unencrypted Backup Storage**: Exported backup files are unencrypted JSON archives containing plain-text metadata and base64-encoded image Blobs. Users must protect exported backup files through secure local filesystem storage.
4. **Browser Cache Eviction Risk**: In aggressive disk-cleanup scenarios or private browsing modes, browser storage may be purged by the host operating system. Users are advised to export regular JSON backups in the `#account` workspace.
