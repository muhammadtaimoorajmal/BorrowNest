## Overview

BorrowNest v0.1.0 marks the initial official release of the BorrowNest local-first item sharing and lending coordination platform. Designed as a privacy-preserving, accessible, and resilient client-side web application, BorrowNest enables neighbors and local communities to catalog household equipment, coordinate borrowing requests, agree on scheduled loan periods, and verify physical item condition at handover and return checkpoints.

---

## Key Features & Capabilities

### 1. Local-First Client Architecture
- **Native Browser IndexedDB Persistence**: Zero external cloud dependency or third-party tracking; all records reside safely in the user's browser environment.
- **Relational Multi-Store Schema (v3)**: Normalized stores for `items`, `photos`, `requests`, and `loans`, supporting atomic transactions, indexes, and referential integrity.
- **Atomic Multi-Store Backup & Restore (v3)**: Complete JSON backup format exporting items, images, requests, and loan checkpoints with schema version validation and transactional rollback protection.

### 2. Item Listing Management & Privacy
- **Listing Lifecycle**: Create, edit, toggle availability (`ACTIVE`, `INACTIVE`), and archive items.
- **Relational Integrity Guards**: Prevent item deletion when request or loan history exists (`ItemHasRequestHistoryError`); block archiving during active loans.
- **Client-Side Media Processing**: Automatic downscaling, aspect ratio preservation, compression to WebP, and complete EXIF/GPS metadata stripping via HTML5 Canvas.
- **Location Privacy (DR-05)**: Enforces coarse neighborhood area indicators only (e.g., "Greenwood / Pine St area"). Exact addresses and access codes are never collected or stored.

### 3. Unified Discovery, Search & Filtering (DR-01)
- **Instant Search & Category Filters**: Multi-field text search with debouncing, category tags, availability filters, and sorting.
- **Modal Detail Inspection**: Accessible modal dialog for viewing item specifications, photos, and borrowing availability without navigating away.

### 4. Structured Borrowing Requests & Scheduling (DR-02 + DR-03)
- **Date Range Selection**: Clear calendar selection for start and return dates.
- **Conflict Prevention**: Deterministic date overlap detection preventing concurrent active or reserved bookings for the same item.
- **Owner Review & Actions**: Approve, decline, and pending-request cancellation workflows.

### 5. Physical Custody Handover & Return Verification (DR-04)
- **Decoupled State Machine**: Distinct separation between request records (`PENDING`, `APPROVED`, `DECLINED`, `CANCELLED`) and physical loan lifecycles (`RESERVED`, `ACTIVE`, `COMPLETED`, `RELEASED_NOT_COLLECTED`).
- **Two-Party Handover**: Owner records initial physical condition (1–5 tier, observations, photos); borrower inspects and confirms receipt within the scheduled calendar window to transition loan to `ACTIVE`.
- **Enforced Return Handshake**: Borrower marks the item physically returned (`borrowerReturnMarkedAt`); only after return marking can the owner conduct return condition inspection to transition loan to `COMPLETED`.
- **Side-by-Side Condition Comparison**: 3-column comparative view across Listing Baseline, Collection Handover, and Return Inspection with objective delta pills and transparency disclaimers.
- **Uncollected Reservation Release**: Owner resolution workflow for elapsed pickup windows, unlocking calendar availability without losing audit records.

## Getting Started

To run BorrowNest locally:

```bash
git clone https://github.com/muhammadtaimoorajmal/BorrowNest.git
cd BorrowNest
git checkout v0.1.0
npm ci
npm run dev
```

To run quality checks:

```bash
npm run lint
npm run test
npm run build
npm audit --omit=dev
```
